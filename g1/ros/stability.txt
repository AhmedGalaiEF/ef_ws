# Stability ROS Plan

Version: 0.1
Target Platform: Unitree G1
Scope: ZMP, support polygon, COM estimation, payload correction, and waist/upper-body balance control

============================================================
1. SYSTEM GOALS
============================================================

The stability system estimates and visualizes humanoid balance state in real time.

It must provide:

- Support polygon visualization
- COM estimation
- Payload-aware COM correction
- ZMP estimation
- Stability margin calculation
- Waist roll/pitch/yaw correction suggestions
- Safety triggers for unstable configurations
- ROS2 topics for RViz/Foxglove debugging
- Logging for analysis and controller tuning

The system is not a replacement for the robot's internal balance controller.
It is a supervisory and corrective layer for upper-body manipulation.

============================================================
7. SUPPORT POLYGON ESTIMATION
============================================================

The support polygon is the convex hull of active foot contact polygons.

For each foot, define sole contact corners in the foot frame:

front-left
front-right
rear-right
rear-left

Example config:

left_foot_frame: left_sole
right_foot_frame: right_sole

foot_length: 0.23
foot_width: 0.10

x_front: 0.14
x_rear: -0.09
y_outer: 0.05
y_inner: -0.05

Transform foot corners into world frame:

p_world = T_world_foot * p_foot

Project to ground:

p_world.z = ground_z

Double support:

support_polygon = convex_hull(left_foot_corners + right_foot_corners)

Single support:

support_polygon = convex_hull(stance_foot_corners)

No contact:

support_polygon invalid

============================================================
8. FOOT CONTACT ESTIMATION
============================================================

Preferred contact source:

- Foot force sensors

If force sensors are unavailable, use heuristics:

left_contact =
    abs(left_foot_z - ground_z) < contact_height_threshold
    and norm(left_foot_velocity) < contact_velocity_threshold

right_contact =
    abs(right_foot_z - ground_z) < contact_height_threshold
    and norm(right_foot_velocity) < contact_velocity_threshold

Example thresholds:

contact_height_threshold: 0.03 m
contact_velocity_threshold: 0.05 m/s

Support modes:

- DOUBLE_SUPPORT
- LEFT_SUPPORT
- RIGHT_SUPPORT
- FLIGHT_OR_UNKNOWN

============================================================
9. ROBOT COM ESTIMATION
============================================================

Simple mode:

COM ~= pelvis position

This is useful for first visualization only.

URDF inertial mode:

For each link:

- get link mass m_i
- get link inertial origin p_link_com_i
- get T_world_link_i from TF or kinematics

Then:

p_robot_com =
    sum(m_i * p_world_link_com_i) / sum(m_i)

Total robot mass:

m_robot = sum(m_i)

Recommended library options:

- Pinocchio
- RBDL
- KDL
- custom URDF parser

============================================================
10. PAYLOAD-AWARE COM CORRECTION
============================================================

When the robot picks up an object, the payload must be included in the COM.

Inputs:

- payload mass M
- payload COM local offset
- attached frame
- transform from attached frame to payload COM

Payload pose:

T_world_payload =
    T_world_attached_frame * T_attached_payload

Payload COM:

p_payload_com =
    T_world_payload * p_payload_com_local

Corrected total COM:

p_total_com =
    (m_robot * p_robot_com + M * p_payload_com)
    /
    (m_robot + M)

If multiple payloads exist:

p_total_com =
    sum(m_i * p_i) / sum(m_i)

The same correction should be applied to COM velocity and acceleration.

============================================================
11. COM VELOCITY AND ACCELERATION
============================================================

Options:

1. Finite difference COM position
2. Use centroidal dynamics library
3. Approximate COM acceleration from hip IMU
4. Fuse IMU and kinematic estimates

Practical first implementation:

- COM position from URDF inertials
- COM velocity from filtered finite difference
- COM acceleration from filtered finite difference or hip IMU

IMU acceleration processing:

a_world_raw = R_world_imu * a_imu
a_world_linear = a_world_raw - gravity_vector

Then low-pass filter:

cutoff: 2 to 5 Hz

Avoid using raw IMU acceleration directly for ZMP.

============================================================
12. ZMP ESTIMATION
============================================================

First implementation: LIPM-style ZMP.

For flat ground:

x_zmp = x_com - z_com / g * xddot_com
y_zmp = y_com - z_com / g * yddot_com
z_zmp = ground_z

Where:

- com is payload-corrected COM
- xddot_com and yddot_com are filtered COM accelerations
- g = 9.81 m/s^2

More accurate implementation:

If foot force-torque data is available:

x_zmp = -tau_y / F_z
y_zmp =  tau_x / F_z

Where the net ground reaction wrench is:

W_ground = [F_x, F_y, F_z, tau_x, tau_y, tau_z]

Do not trust ZMP if:

- F_z is too small
- contact state is unknown
- IMU acceleration is saturated
- robot is jumping or falling
- support polygon is invalid

============================================================
13. STABILITY MARGIN
============================================================

The main stability test:

ZMP inside support polygon.

Compute:

- stable = point_inside_polygon(zmp_xy, support_polygon)
- margin = distance from ZMP to closest polygon edge

Signed margin convention:

- positive: inside support polygon
- zero: on boundary
- negative: outside support polygon

Normalized margin:

normalized_margin =
    signed_margin / characteristic_support_width

Recommended states:

STABLE
LOW_MARGIN
CRITICAL
UNSTABLE
UNKNOWN

Example thresholds:

stable_margin: > 0.04 m
low_margin: 0.02 to 0.04 m
critical_margin: 0.00 to 0.02 m
unstable: < 0.00 m

============================================================
14. WAIST BALANCE CONTROL
============================================================

The waist is used as a COM/ZMP correction mechanism.

It should not fight the robot's internal whole-body balance controller.

Reference point:

p_ref = support_polygon_center + payload_bias

Error:

e = p_ref - p_zmp

Derivative:

de = (e - e_prev) / dt

Waist correction:

pitch_delta = Kp_x * e.x + Kd_x * de.x
roll_delta  = -Kp_y * e.y - Kd_y * de.y
yaw_delta   = 0

Command:

waist_pitch_cmd = pitch_nominal + pitch_delta
waist_roll_cmd  = roll_nominal  + roll_delta
waist_yaw_cmd   = yaw_nominal   + yaw_delta

Interpretation:

ZMP too far forward:
    pitch torso backward

ZMP too far backward:
    pitch torso forward

ZMP too far left:
    roll torso right

ZMP too far right:
    roll torso left

Yaw is usually not used for balance correction.

============================================================
15. PAYLOAD BIAS
============================================================

When holding a payload, bias the desired ZMP away from the payload direction.

If payload is held forward:

- choose p_ref slightly backward inside the support polygon

If payload is held left:

- choose p_ref slightly right inside the support polygon

Example:

payload_offset_xy = p_payload_com.xy - p_support_center.xy

p_ref =
    support_center - k_payload_bias * payload_offset_xy

Clamp p_ref to stay safely inside the support polygon.

============================================================
16. WAIST COMMAND LIMITS
============================================================

Use smooth bounded corrections.

Recommended limits:

max_roll_correction: 5 to 10 deg
max_pitch_correction: 5 to 10 deg
max_yaw_correction: 0 to 5 deg

max_roll_rate: 10 to 30 deg/s
max_pitch_rate: 10 to 30 deg/s
max_yaw_rate: 10 to 30 deg/s

Use:

- low-pass filtering
- rate limiting
- acceleration limiting
- joint limit clamping

Do not use high-gain sudden waist corrections while carrying payloads.

============================================================
17. WHOLE-BODY RECOVERY PRIORITY
============================================================

If margin becomes small, recovery should happen in this order:

1. Stop arm or payload motion
2. Bring payload closer to torso
3. Shift waist roll/pitch
4. Bend knees or adjust hip posture
5. Widen stance or step
6. Retreat or place payload down

The waist controller alone is not enough for heavy or extended payloads.

============================================================
18. SAFETY SUPERVISOR
============================================================

Safety triggers:

- ZMP outside support polygon
- stability margin below critical threshold
- payload too far from support center
- torso tilt too large
- foot contact lost
- joint torque too high
- arm tracking error too high
- waist correction saturated
- human or obstacle too close

Safety actions:

LOW_MARGIN:
    slow arm motion
    reduce payload acceleration
    bias payload toward torso

CRITICAL:
    stop arm motion
    hold payload
    command waist correction
    prepare recovery

UNSTABLE:
    stop task
    retract arm
    lower payload if safe
    request stepping recovery
    notify operator

UNKNOWN:
    freeze nonessential motion
    maintain safe posture

============================================================
24. VALIDATION TESTS
============================================================

Static tests:

- robot standing, no payload
- robot leaning forward
- robot leaning left/right
- robot holding known mass near torso
- robot holding known mass far forward

Dynamic tests:

- slow arm extension
- slow payload lift
- slow waist correction
- small commanded torso tilt
- support transition if available

Pass criteria:

- COM moves in expected direction
- ZMP stays within support polygon for stable postures
- margin decreases when payload is extended
- margin improves when payload is pulled inward
- waist correction direction matches expected balance response

============================================================
25. FAILURE MODES
============================================================

Known failure cases:

- inaccurate URDF inertials
- wrong foot frame offsets
- bad ground height
- IMU bias
- unfiltered acceleration
- false foot contact detection
- unknown payload mass
- slipping payload
- internal robot controller fighting waist corrections

Mitigations:

- calibrate foot sole frames
- validate masses and inertias
- low-pass filter acceleration
- fuse multiple contact signals
- limit waist corrections
- keep human override available
- start in visualization-only mode

============================================================
26. DESIGN PRINCIPLES
============================================================

Core rule:

Do not use waist motion to hide unsafe payload configurations.

Preferred strategy:

- keep payload close
- move slowly
- monitor ZMP
- keep margin high
- use waist correction gently
- step or replan if needed

Stability authority hierarchy:

Internal robot stabilizer
    >
Safety supervisor
    >
Waist balance controller
    >
Upper-body task controller
    >
VLA or skill planner
