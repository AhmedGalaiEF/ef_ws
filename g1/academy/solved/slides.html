Course Intro 12 · ROS 2

Intro to ROS 2

ROS 2 (this academy: Foxy) is a pub/sub + services + actions middleware for robotics: independent nodes exchange typed messages on named topics, with no node needing to know who else is listening.

  • Unitree runs its own DDS layer (via unitree_sdk2py's ChannelPublisher/ChannelSubscriber) on top of the same CycloneDDS transport ROS 2 uses — with RMW_IMPLEMENTATION=rmw_cyclonedds_cpp, a DDS topic rt/<name> and a ROS 2 topic /<name> are the same wire data.
  • Most tasks in this course use unitree_sdk2py's Channel API directly (no rclpy node needed) — it is simpler for one-off scripts/notebooks.
  • The bonus ROS 2 package track (and the cmd_vel → LocoClient bridge) uses rclpy nodes/publishers/subscribers directly, for when you need a long-running ROS 2 node instead of a notebook cell.
Check ROS 2 is reachable: `source /opt/ros/foxy/setup.bash && ros2 topic list` should show `rt/...`-derived Unitree topics as `/...`.

Knowledge Task 2

Knowledge — ChannelFactory is global process state

ChannelFactoryInitialize(domain_id, interface) sets up the DDS participant for the whole process. It is not per-object, per-topic, or per-notebook-cell — it is one shared state for the entire Python process (kernel).

  • Call it exactly once, before constructing any ChannelSubscriber/ChannelPublisher.
  • Always the same (domain_id, interface) for the life of that process — a second call with different settings must not silently reconnect (that would leave half your subscribers on the old settings).
  • In Jupyter, "restart the kernel" is your reset button when you need a different interface/domain — not a workaround, the intended way.
DDS setup order: factory once, then as many publishers/subscribers as you need.
Knowledge Task 2

Knowledge — subscriber callbacks are asynchronous

A ChannelSubscriber callback runs on a background thread whenever a message arrives. Between messages, whatever you cached last time is all you have — it can be None (nothing received yet) or stale (publisher died, wrong topic/domain/interface).

  • The fix is one small class: cache the newest message + its time.time() receipt time, and expose a fresh(max_age_s) check so every later call site can refuse stale data in one line instead of repeating the staleness math.

Solution Task 2

Solution — ensure_channel_factory + Latest

Full version, plus the two small helpers every later task also reuses from lib_solved.py: make_publisher and diagnose.

_factory_config = None
def ensure_channel_factory(domain_id, interface):
    global _factory_config
    config = (int(domain_id), str(interface))
    if _factory_config is None:
        ChannelFactoryInitialize(*config)
        _factory_config = config
    elif _factory_config != config:
        raise RuntimeError(f"ChannelFactory already initialized as {_factory_config}; restart kernel for {config}.")
    return _factory_config

class Latest:
    def __init__(self, topic, message_type, queue_len=10):
        self.message = None
        self.timestamp = 0.0
        self.subscriber = ChannelSubscriber(topic, message_type)
        self.subscriber.Init(self._callback, queue_len)
    def _callback(self, message):
        self.message = message
        self.timestamp = time.time()
    def fresh(self, max_age_s=0.5):
        return self.message is not None and time.time() - self.timestamp <= max_age_s

def make_publisher(topic, message_type):
    publisher = ChannelPublisher(topic, message_type)
    publisher.Init()
    return publisher

class HeadlightThread(threading.Thread):
    def __init__(self, audio_client, rgb, duration_s, interval_s, stop_event):
        super().__init__(daemon=False)
        self.audio_client, self.rgb = audio_client, rgb
        self.duration_s, self.interval_s = max(0.0, duration_s), max(0.0, interval_s)
        self.stop_event = stop_event
    def run(self):
        end_time = time.monotonic() + self.duration_s
        try:
            while not self.stop_event.is_set() and time.monotonic() < end_time:
                code = int(self.audio_client.LedControl(*self.rgb))
                if code != 0:
                    self.stop_event.set(); break
                self.stop_event.wait(self.interval_s)
        finally:
            try: self.audio_client.LedControl(0, 0, 0)      # always attempt off
            except Exception: pass

def set_headlight(color="green", intensity=100, duration_s=3):
    global _headlight_stop, _headlight_thread
    rgb = scale_color(parse_color(color), intensity)
    if _headlight_thread is not None and _headlight_thread.is_alive():
        _headlight_stop.set(); _headlight_thread.join()      # stop+join before starting a new one
    code = int(audio_client.LedControl(*rgb))
    if code != 0 or duration_s <= 0:
        return code
    _headlight_stop = threading.Event()
    _headlight_thread = HeadlightThread(audio_client, rgb, duration_s, 0.2, _headlight_stop)
    _headlight_thread.start()
    return code

    state = _custom_mode_state

def odom_move(target_dx, target_dy, target_dyaw, pos_tol_m=0.05, yaw_tol_rad=0.05, timeout_s=15.0, poll_s=0.2):
    if not _locomotion_lock.acquire(blocking=False):
        raise RuntimeError("Another locomotion command is already in progress.")
    try:
        start = _odom_pose()
        if start is None:
            raise RuntimeError("No fresh odometry; cannot monitor arrival.")
        code = int(loco.Move(target_dx, target_dy, target_dyaw, continous_move=False) or 0)
        if code != 0:
            return {"code": code, "arrived": False, "reason": "move request rejected"}
        deadline = time.time() + timeout_s
        while time.time() < deadline:
            pose = _odom_pose()
            if pose is not None:
                dx, dy, dyaw = pose[0]-start[0], pose[1]-start[1], pose[2]-start[2]

        loco_stop()
        return {"code": code, "arrived": False, "reason": "timeout"}
    finally:
        _locomotion_lock.release()

def write_arm_sdk_pose(targets, weight=1.0, kp=30.0, kd=1.5, waist_kp=480.0, waist_kd=12.0):
    msg = unitree_hg_msg_dds__LowCmd_(); msg.mode_pr = 0; msg.mode_machine = 0
    msg.motor_cmd[29].q = max(0.0, min(1.0, weight))          # the arm_sdk enable/weight byte

        cmd.mode = 1; cmd.q = float(q); cmd.dq = 0.0; cmd.tau = 0.0
        cmd.kp = waist_kp if int(joint) in WAIST_JOINTS else kp

    msg.crc = _crc.Crc(msg)

def _ease(ratio):

def ik_move_ee(hand, dx=0.0, dy=0.0, dz=0.0, max_speed=0.25, max_dq=0.15, rate_hz=50.0):
    side = "right" if str(hand).lower().startswith("r") else "left"
    joints = RIGHT_ARM_JOINTS if side == "right" else LEFT_ARM_JOINTS
    current = current_upper_body_pose()
    q_init = np.array([current[j] for j in joints])
    fk = fk_solver(side)
    target_T = fk.compute_arm(q_init).copy()
    target_T[0, 3] += dx
    target_T[1, 3] += dy if side == "left" else -dy            # mirrored sign by side
    target_T[2, 3] += dz
    q_sol, info = ik_solver(side).solve(target_T, q_init=q_init)
    if q_sol is None:
        return {"success": False, "ik": info}                  # never move on a failed solve
    delta = np.clip(np.asarray(q_sol) - q_init, -max_dq, max_dq)
    target_q = q_init + delta
    target = dict(current)
    for i, j in enumerate(joints): target[j] = float(target_q[i])
    remaining = max(abs(target[j] - current[j]) for j in joints)
    steps = max(1, int(np.ceil(remaining / max(1e-4, max_speed / rate_hz))))
    for step in range(1, steps + 1):
        smooth = _ease(step / steps)                            # same ease curve as Task 8
        frame = {j: current[j] + (target[j]-current[j])*smooth for j in joints}
        write_arm_sdk_pose({**current, **frame})
        time.sleep(1.0 / rate_hz)
    return {"success": True, "ik": info, "steps": steps}

def write_hand(targets, side="right", kp=0.8, kd=0.05, tau=0.02):
    msg = unitree_hg_msg_dds__HandCmd_()
    for i, q in enumerate(targets):
        cmd = msg.motor_cmd[i]
        cmd.mode = (i & 0x0F) | (1 << 4); cmd.q = float(q)
        cmd.dq = 0.0; cmd.tau = tau; cmd.kp = kp; cmd.kd = kd
    hand_pubs[side].Write(msg)
    _last_hand_targets[side] = list(targets)

def gradual_close(threshold, side="right", steps=40, delay_s=0.05):
    start = _last_hand_targets.get(side, HAND_OPEN[side])
    for step in range(1, steps + 1):
        a = step / steps
        frame = [x + (y-x)*a for x, y in zip(start, HAND_CLOSED[side])]
        write_hand(frame, side=side)
        time.sleep(delay_s)
        samples = tactile_samples(side)
        if samples and max(samples) >= threshold:               # stop the moment contact is felt
            return {"contact": True, "step": step, "side": side}
    return {"contact": False, "step": steps, "side": side}       # closed fully, never touched anything

def validated_target(pipeline, frame, marker_length_m, min_confidence=0.5,
                       max_age_s=1.0, prompt="the delivery package"):
    if time.time() - frame.get("timestamp", time.time()) > max_age_s:
        raise RuntimeError("RGB-D frame is stale.")                       # refusal #1
    rgb = cv2.imdecode(np.frombuffer(frame["rgb_jpeg"], dtype=np.uint8), cv2.IMREAD_COLOR)
    detection = pipeline.detect_object(frame["rgb_jpeg"], prompt)
    if detection.confidence < min_confidence:
        raise RuntimeError(f"Low-confidence detection ({detection.confidence}); refusing to act.")  # refusal #2
    marker_pose = pipeline.aruco_pose(rgb, marker_length_m)
    return pipeline.marker_to_palm_target(marker_pose)

Solution — DemoNode

import rclpy
from rclpy.node import Node
from std_msgs.msg import String

class DemoNode(Node):
    def __init__(self):
        super().__init__("academy_demo")
        self.pub = self.create_publisher(String, "/academy/demo_status", 10)
        self.sub = self.create_subscription(String, "/academy/demo_status", self.on_status, 10)
        self.timer = self.create_timer(1.0, self.publish_status)   # 1 Hz heartbeat
    def publish_status(self):
        msg = String(); msg.data = "academy demo alive"
        self.pub.publish(msg)
    def on_status(self, msg):
        self.get_logger().info(msg.data)

Solution — Robot

class Robot:
    _factory_config = None                                   # class-level guard, same idea as Task 2
    def __init__(self, interface="eth0", domain_id=0):
        config = (int(domain_id), str(interface))
        if Robot._factory_config is None:
            ChannelFactoryInitialize(*config); Robot._factory_config = config
        elif Robot._factory_config != config:
            raise RuntimeError("Restart kernel before changing DDS interface/domain.")
        self.loco = LocoClient(); self.loco.SetTimeout(5.0); self.loco.Init()
        self.switcher = MotionSwitcherClient(); self.switcher.SetTimeout(5.0); self.switcher.Init()
        self.audio = AudioClient(); self.audio.SetTimeout(5.0); self.audio.Init()
    def stop(self):
        return self.loco.StopMove()
    def state_summary(self):
        code, mode = self.switcher.CheckMode()
        return {"motion_code": int(code), "motion_mode": mode}   # read-only, commands nothing

Solution — voice_chat_turn

latest_audio = {"text": None, "timestamp": 0.0}
def on_audio(message):
    latest_audio["text"] = message.data
    latest_audio["timestamp"] = time.time()
audio_sub = ChannelSubscriber("rt/audio_msg", String_); audio_sub.Init(on_audio, 20)

def voice_chat_turn(robot, integration_module="academy_asr_openai", language="en"):
    if not latest_audio["text"] or time.time() - latest_audio["timestamp"] > 3.0:
        raise RuntimeError("No fresh wake-up audio message.")           # same freshness discipline as Task 2
    integration = load_provided_pipeline(integration_module)
    reply = integration.chat(integration.transcribe(latest_audio["text"]))
    play_piper_text(robot.audio, reply, language=language)              # Task 3
    return reply

Knowledge Bonus: RAG

Knowledge — the RAG pipeline shape

  • Chunk by heading/section, not fixed character counts — keep chunks small enough that several fit alongside the system prompt.
  • Cache embeddings locally (a .json/.npy file) keyed by chunk hash so re-runs don't re-embed unchanged content.
  • Start with a flat in-memory vector store (list of vectors + cosine similarity) before reaching for Chroma/FAISS/Qdrant — it's enough to demonstrate retrieval correctness on a small corpus.

Knowledge Bonus: Simulation

Knowledge — the RL loop (why Isaac Lab is different)

MuJoCo/Gazebo simulate physics for you to script against directly (the same shape as Tasks 2–13). Isaac Lab instead wraps the sim in a standard reinforcement-learning environment API — a policy is trained by trial and error across thousands of parallel copies, not scripted.

  • Observation: sensor/state readout (joint q/dq, IMU, ... — the same signals Task 4's get_lowstate() reads on the real robot).
  • Action: what the policy outputs each step — often joint targets or torques, the same shape as Task 9's move_ll_joint command.
  • Reward: a scalar the training loop tries to maximize (e.g. forward velocity minus energy cost) — defining a good reward is most of the work.
  • A trained policy is exported and connected to this course's real loco_move/ik_move_ee the same way any other controller would be — Isaac Lab produces the policy, it doesn't replace the SDK plumbing around it.
