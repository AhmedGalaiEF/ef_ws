Task 6 — Basic Locomotion Helpers

Two locomotion helpers, both built on the native LocoClient: loco_move runs a bounded-duration continuous velocity command and always stops in finally; odom_move issues a single non-continuous relative move and closes the loop on odometry to confirm arrival, instead of treating the RPC return code alone as proof of motion. A simple lock prevents two locomotion commands from running concurrently.

§1Knowledge — continuous vs. non-continuous Move

LocoClient.Move(vx, vy, vyaw, continous_move=...) behaves differently depending on that flag, and neither mode tells you the robot actually arrived.

ModeBehaviorHow this course confirms completion
continous_move=Truekeeps moving at that velocity until told otherwisesleep(duration_s) then always call StopMove(), even on exception (finally)
continous_move=Falseone relative-displacement requestpoll odometry until observed displacement is within tolerance — the RPC return code alone is not proof of arrival

Flow for odom_move: record start odom pose → send Move() (non-continuous) → poll odom pose until |err| < tol → arrived/timeout → stop.

§2Knowledge — one lock, one command at a time

A simple non-blocking threading.Lock() (acquire(blocking=False)) guarantees only one locomotion command runs at a time — a second call while one is already sleeping/polling raises immediately instead of silently queueing behind it or racing it.

Both helpers release the lock in finally, so an exception mid-command can never leave locomotion permanently "locked out".

Yaw error uses a wrapped ((err + π) % 2π) - π comparison — naive subtraction breaks near the ±π wraparound.

    def __init__(self, topic, message_type, queue_len=10):
        self.message = None; self.timestamp = 0.0
        self.subscriber = ChannelSubscriber(topic, message_type)
        self.subscriber.Init(self._callback, queue_len)
    def _callback(self, message):
        self.message = message; self.timestamp = time.time()

odom_sub = Latest("rt/odommodestate", SportModeState_)
loco = LocoClient(); loco.SetTimeout(5.0); loco.Init()
_locomotion_lock = threading.Lock()

def _odom_pose():
    msg = odom_sub.message
    if msg is None:
        return None
    return (float(msg.position[0]), float(msg.position[1]), float(msg.imu_state.rpy[2]))

def loco_stop():
    if hasattr(loco, "StopMove"):
        return loco.StopMove()
    return loco.Move(0.0, 0.0, 0.0, continous_move=False)

A continuous velocity command held for a fixed duration, always cancelled in finally — so an exception mid-sleep (kernel interrupt, timeout) can never leave the robot moving.

def loco_move(vx, vy, vyaw, duration_s=2.0):
    if not _locomotion_lock.acquire(blocking=False):
        raise RuntimeError("Another locomotion command is already in progress.")
    try:
        code = int(loco.Move(vx, vy, vyaw, continous_move=True) or 0)
        try:
            time.sleep(duration_s)
        finally:
            loco_stop()             # ALWAYS stop, even on exception mid-sleep
        return code
    finally:
        _locomotion_lock.release()

Issue one non-continuous Move request for the relative displacement, then poll odometry until the observed displacement is within tolerance, the request was rejected, or timeout_s elapses.

def odom_move(target_dx, target_dy, target_dyaw, pos_tol_m=0.05, yaw_tol_rad=0.05, timeout_s=15.0, poll_s=0.2):
    if not _locomotion_lock.acquire(blocking=False):
        raise RuntimeError("Another locomotion command is already in progress.")
    try:
        start = _odom_pose()
        if start is None:
            raise RuntimeError("No fresh odometry; cannot monitor arrival.")
        code = int(loco.Move(target_dx, target_dy, target_dyaw, continous_move=False) or 0)
        if code != 0:
            return {"code": code, "arrived": False, "reason": "move request rejected"}
        deadline = time.time() + timeout_s
        while time.time() < deadline:
            pose = _odom_pose()
            if pose is not None:
                dx, dy, dyaw = pose[0]-start[0], pose[1]-start[1], pose[2]-start[2]
                err_pos = ((target_dx-dx)**2 + (target_dy-dy)**2) ** 0.5
                err_yaw = abs(((target_dyaw-dyaw) + math.pi) % (2*math.pi) - math.pi)
                if err_pos <= pos_tol_m and err_yaw <= yaw_tol_rad:
                    return {"code": code, "arrived": True, "moved": (dx, dy, dyaw)}
            time.sleep(poll_s)
        loco_stop()
        return {"code": code, "arrived": False, "reason": "timeout"}
    finally:
        _locomotion_lock.release()

The RPC return code alone is never proof of arrival for odom_move — only the polled odometry comparison counts.
