§1Knowledge — loco_move's timing

CallBehavior
loco_move(vx, vy, vyaw, duration_s=2)drives for exactly duration_s seconds, then auto-stops (calls loco_stop() for you) — the common case
loco_move(vx, vy, vyaw, duration_s=None)fires one Move() RPC and returns immediately, no auto-stop — only use this when you are managing the stop yourself (e.g. sending (0,0,0) should not itself block)
loco_stop()stops immediately — call any time you need to bail out of a move early

vx/vy are in m/s (forward/strafe), vyaw in rad/s. Start small (e.g. 0.15 m/s) with a spotter in a clear space.

§2Knowledge — chaining moves into a path

  • A path is just several loco_move(...) calls back to back — forward, turn, forward, turn, forward traces an approximate "U" shape in 3 legs.
  • Keep the stop points as data (a list), and let a small callback run at each stop — this is exactly the hook Day 3's Task 1 reuses to play a different arm gesture at each stop of the same U path.
  • get_odom() before and after each leg is your ground truth for how far the robot actually went — open-loop timing drifts.

def walk_u_path(g1, vx=0.15, vyaw=0.5, leg_s=2.0, turn_s=1.2, pause_s=1.0, on_stop=None):
    legs = [(vx, 0.0, 0.0, leg_s), (0.0, 0.0, vyaw, turn_s),
            (vx, 0.0, 0.0, leg_s), (0.0, 0.0, vyaw, turn_s),
            (vx, 0.0, 0.0, leg_s)]
    stop_index = 0
    for i, (lvx, lvy, lvyaw, duration_s) in enumerate(legs):
        g1.loco_move(lvx, lvy, lvyaw, duration_s=duration_s)
        if i % 2 == 0:  # after each straight leg, we are at a stop point
            if on_stop is not None:
                on_stop(g1, stop_index)
            time.sleep(pause_s)
            stop_index += 1
    g1.loco_stop()

Keep this helper around. Day 3's Task 1 imports/reuses walk_u_path unchanged and only supplies a new on_stop callback that plays a high-level arm gesture at each stop.
