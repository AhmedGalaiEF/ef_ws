§1Knowledge — three separate control surfaces

LocoClient, MotionSwitcherClient, and RobotStateClient answer three different questions — changing one does not resolve the others.

ClientAnswersUsed for
LocoClient"what FSM state is locomotion in?"SetFsmId, Move, Damp
MotionSwitcherClient"which service currently owns the motors?"CheckMode, SelectMode, ReleaseMode
RobotStateClient"which named services are registered/enabled?"ServiceList, ServiceSwitch

§2Knowledge — the full FSM table

Do not invent an id beyond this table. This academy's G1 units run waist-locked (only WaistYaw is a free joint), so walk/balanced-stand is FSM 500, not the waist-unlocked variant's 501.

IDNameTypical use
0Zero-Torquemotors off — safe to handle legs
1Dampviscous damping only (soft) — default power-on, always-available fallback
3Sitdog-sit posture
4Stand-up / preparefirmware-defined stand, good after Damp
500Start / walkbalance controller & gait planner (waist-locked units)
802Runrunning gait

This course's FSM_IDS = {"zero_torque": 0, "damp": 1, "prepare": 4, "walk": 500, "run": 802} covers the five you'll actually use.

Do not use id 2, and do not trust ids 702/706 without independently verifying them. An earlier version of this page (and of day2_slides.html) listed 2 as "Squat" and 702/706 as confirmed stand-up transitions. academy/mappings_and_constraints.html — this repo's own audited FSM reference, cross-checked against sdk_wrapper.py and other academy scripts — traces id 2 to an unlabeled/"airborne" placeholder (fsm_2_squat_placeholder in dev code) and explicitly warns not to map an undocumented FSM id. Ids 702 and 706 do not appear in that reference at all. Treat only 0/1/3/4/500/802 as confirmed for this hardware.

§3Knowledge — damp as the universal safe fallback

damp (FSM id 1) is the one mode this course treats as always available: bounded joint damping, no locomotion authority. Call damp_mode() before an emergency stop, and before releasing controller ownership of any other publisher — it's the landing pad every controller handoff in this course falls back to.

toggle_gait() prefers SetBalanceMode/SetGaitType where the installed SDK exposes them, falling back to BalanceStand/SetFsmId("walk") — and always inspects the return code instead of assuming success.

toggle_service flips a named RobotStateClient service on/off based on its currently reported status.

def get_service(name):
    code, rows = robot_state_client.ServiceList()
    if int(code) != 0:
        raise RuntimeError(f"ServiceList failed: {code}")
    for row in rows or []:
        if str(getattr(row, "name", "")).strip().lower() == str(name).strip().lower():
            return row
    return None

def toggle_service(name):
    row = get_service(name)
    if row is None:
        raise ValueError(f"Unknown service: {name}")
    enabled = getattr(row, "status", 0) != 0
    code = int(robot_state_client.ServiceSwitch(row.name, bool(enabled)))
    return {"name": row.name, "enabled": enabled, "code": code}

toggle_gait prefers SetBalanceMode/SetGaitType where exposed, falls back to BalanceStand/SetFsmId("walk"):

_gait_state = {"gait": 0}

def toggle_gait():
    target = 0 if _gait_state["gait"] else 1
    if target:
        for method_name in ("SetBalanceMode", "SetGaitType"):
            if hasattr(loco, method_name):
                code = int(getattr(loco, method_name)(1))
                if code == 0:
                    _gait_state["gait"] = 1
                    return {"gait": 1, "method": method_name, "code": code}
    else:
        if hasattr(loco, "BalanceStand"):
            loco.BalanceStand(0)
        for method_name in ("SetBalanceMode", "SetGaitType"):
            if hasattr(loco, method_name):
                getattr(loco, method_name)(0)
        code = int(loco.SetFsmId(FSM_IDS["walk"]))
        if code == 0:
            _gait_state["gait"] = 0
            return {"gait": 0, "method": "SetFsmId(walk)", "code": code}
    return {"gait": _gait_state["gait"]}

_NAMED_COLORS = {"white": (255,255,255), "red": (255,0,0), "green": (0,255,0), "blue": (0,0,255),
                  "yellow": (255,255,0), "cyan": (0,255,255), "magenta": (255,0,255),

def parse_color(value):
    if isinstance(value, tuple) and len(value) == 3:
        return tuple(int(max(0, min(255, v))) for v in value)
    value = str(value).strip().lower()
    if value in _NAMED_COLORS:
        return _NAMED_COLORS[value]
    if re.fullmatch(r"#?[0-9a-fA-F]{6}", value):
        value = value.lstrip("#")
        return (int(value[0:2],16), int(value[2:4],16), int(value[4:6],16))
    raise ValueError("color must be a name or #RRGGBB")

def set_headlight_once(rgb):
    return int(audio_client.LedControl(*rgb))

First call for a given mode_name announces it with Piper, switches the FSM, and starts a background thread that keeps refreshing the requested headlight color every 0.2s. Calling it again (same name, or any other name) cleanly exits: signal the thread, join it, turn the light off, and fall back to damp_mode() for a safe state transition. The interesting part is that entering and exiting use the same function name with no separate "stop" call — a state dict decides which branch runs.

_custom_modes = {
    "greet": {"fsm": None, "announce": "Hello! I'm ready to help."},
    "patrol": {"fsm": "walk", "announce": "Starting patrol mode."},
}
_custom_mode_state = {"active": None, "stop": None, "thread": None}

def _exit_custom_mode():
    state = _custom_mode_state
    if state["thread"] is not None:
        state["stop"].set(); state["thread"].join()
    left = state["active"]
    if left != "greet":            # greet is presentation-only: never switch FSM on exit
        damp_mode()
    state.update(active=None, stop=None, thread=None)
    return {"exited": left}

def toggle_custom_mode(mode_name, language="en", voice=None, headlight_color="green"):
    if _custom_mode_state["active"] == mode_name:
        return _exit_custom_mode()                       # same name again -> exit
    if _custom_mode_state["active"] is not None:
        _exit_custom_mode()                               # a different mode was active -> exit it first
    spec = _custom_modes[mode_name]
    say(spec["announce"], language=language)
    fsm_code = None if spec["fsm"] is None else int(loco.SetFsmId(FSM_IDS[spec["fsm"]]))
    rgb, stop_event = parse_color(headlight_color), threading.Event()
    def worker():
        while not stop_event.is_set():
            set_headlight_once(rgb); stop_event.wait(0.2)
        set_headlight_once((0, 0, 0))
    thread = threading.Thread(target=worker, daemon=False); thread.start()
    _custom_mode_state.update(active=mode_name, stop=stop_event, thread=thread)
    return {"mode": mode_name, "fsm_code": fsm_code}

greet is presentation-only: it must never switch FSM or damp on exit; motion-owning modes (like patrol) may use their explicit FSM and the damp fallback.
